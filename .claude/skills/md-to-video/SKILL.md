# md-to-video

Pipeline root: the git repo root (the folder that contains `.claude/`, `scripts/`, `remotion-app/`; call it `$P`). Always `cd $P` first.
Input: path to a `.md` file (argument). Optional user hints: length, audience, voice, captions, style.

## Steps

-1. **Dependency check.** `cd $P && python3 scripts/check_deps.py`. If it exits non-zero, read `$P/README.md`, do its Setup section for the missing items only (tell the user what you are installing; `sudo` steps: ask the user to run them with the `!` prefix), rerun the check until it passes, then continue. Network is needed for setup.

0. **Ask preferences first** (one AskUserQuestion call, 4 questions; skip any the user already answered in their message):
   - **Theme:** options `Dark technical (Recommended)` = default; `Sketchnote black board` = hand-drawn look (`"theme": {"style": "sketchnote"}`, see prompts/scenes.md); `Custom` = user describes it (follow up with a free-text question if they pick Other/Custom and gave no detail). Map the description to the `theme` object in `prompts/scenes.md` (mode, bg, text, muted, 2 to 4 accent gradient pairs).
   - **Voice:** options `Default: am_liam (Recommended)`; `Pick another voice` (offer af_heart, af_bella, bf_emma, am_michael, bm_george; any id from `python scripts/test_voice.py --list` works); `Multiple voices / two hosts` (then ask for the voices).
   - **Video style:** options `Technical educational (Recommended)` = default; `Custom` (follow up asking what style: e.g. marketing pitch, casual explainer, executive summary, storytelling; also ask target length only if they care). Style steers tone, depth and scene mix in the script.
   - **Conversation style:** how the md becomes narration. Never read the md aloud word for word unless passthrough is chosen. Options:
     - `Rephrased narration (Recommended)` = default; the md's facts restated in plain spoken sentences.
     - `Interview`: converts the doc into Q&A between two different voices (host asks, expert answers). Generated by two subagents: one writes the questions from the md, the other answers them from the md only. Merged into `A:` / `B:` lines (see prompts/script.md).
     - `Direct passthrough`: narrate the md words as written. Drop only markdown symbols (#, *, |, link URLs, code fences); no rewording, no added content. Tables read row by row.
     - `Explainer`: teacher tone. Explain each concept carefully, with an analogy and a concrete example per main idea. Still lossless. Every main idea gets a graphic or animation (see Explainer visuals below).
   - **Voice for Interview:** if the user picked a single voice, the expert uses `af_bella` (or `am_michael` when the host is already `af_bella`). Set it as the `"voices"` map.
1. **Set up job.** `job` = kebab-case slug of the md filename. `mkdir -p $P/jobs/<job>`; copy md to `jobs/<job>/source.md` (skip if already there). Remember the md's absolute path and folder.
2. **Script.** Read `source.md` fully. Follow `prompts/script.md` (next to this file) for the chosen conversation style. Interview style: first two subagents (one questions, one answers, both reading `source.md` only), then merge into `A:` / `B:` lines. Write `jobs/<job>/script.md`. Show the user a 3-line summary of the scene plan; do not stop unless they asked for review.
2b. **Pronunciation pass.** Before scenes are built, list every technical term, acronym, product and name in the script. For each one, check `scripts/pronunciations_seed.json` and `build.py` PRONUNCIATIONS. Add any missing to `jobs/<job>/pronunciations.json` (e.g. `"SQL": "sequel"`, `"GraphQL": "graph Q L"`, `"Kubectl": "kube control"`). Spell out acronyms the first time they appear in narration if the spoken form is unclear. The map must be final before audio runs (see Learnings).
3. **Scenes.** Follow `prompts/scenes.md`. Write `jobs/<job>/scenes.json`.
   - Images: find openly licensed images online (WebSearch), download ONLY via `python scripts/fetch_image.py <job> <url> <name> "<credit>"`. Skip images if none are good; never fabricate URLs.
   - **Long md (more than about 2,500 words, 40+ scenes): write scenes in parallel.** Split `source.md` at section boundaries into chunks of about 1,000 to 1,500 words (`grep -n '^## ' source.md`), one subagent each, all launched in one turn. Brief each with `prompts/subagent_scenes.md` (fill in job, line range, id prefix p1, p2, ...). Each writes `jobs/<job>/parts/script_N.md` and `parts/scenes_N.json` (an array) and checks it with `.venv/bin/python scripts/check_part.py <file>`. The first chunk owns the `title` scene, the last owns the `outro`. Then `python scripts/merge_parts.py <job> [--theme sketchnote]` writes `scenes.json` and `script.md` with the shared pronunciation seed (`scripts/pronunciations_seed.json`; add job-specific words in `jobs/<job>/pronunciations.json`) and reports scene count, duplicate ids and minutes. Run `build.py <job> --audio-only` next to validate everything. 8 agents wrote 228 scenes in about 9 minutes.
4. **Build.** `source .venv/bin/activate && python scripts/build.py <job> --out "<md folder>/<md name>.mp4"`. Runs: validate, Kokoro audio (cached), Remotion per-scene mp4 (cached by content hash), ffmpeg concat to `jobs/<job>/final.mp4`.
   - Validation errors: fix `scenes.json`, rerun.
   - Preview one scene fast: `python scripts/build.py <job> --only <scene-id>`.
   - **Partial output** (user wants "the first N scenes for now"): `python scripts/build.py <job> --first N --out "<path>.mp4"`. It renders and joins only the first N scenes into `jobs/<job>/final.part.mp4` and never touches `final.mp4`. Build the rest later with the normal command; cached scenes are reused. `--only` alone skips the concat, so do not use it for partial videos.
   - A scene's render hash includes every file in `remotion-app/src`, so any template or style edit re-renders every scene. Finish template edits before the big render, and do not edit `src` while a render is running.
   - First look: `cd remotion-app && npx remotion still Scene out/f.png --props=<file> --frame=90` or `npx remotion studio`.
5. **Verify.** `ffprobe` final duration ~ sum of scene durations. Extract 3 frames with ffmpeg and view them with Read to check layout (text overflow, empty areas). Fix and rebuild only affected scenes.
6. **Report.** The final video is saved next to the source md as `<md folder>/<md name>.mp4` (also kept at `jobs/<job>/final.mp4`). Report that path, duration, scene list, any images and their credits. Terse.

## Editing later
- Change narration/visuals of one scene: edit `scenes.json`, rerun build. Only that scene's audio and video regenerate.
- Voices: single `"voice"`, or `"voices"` map + per-scene `"speaker"` / dialogue `narration` list (see prompts/scenes.md). Ask the user for host voices if they want more than one.
- Default voice is `am_liam`. Change voice: set `"voice"` (list with `python scripts/test_voice.py --list`). Mispronounced word: add to `"pronunciations"` in scenes.json.
- Studio preview: `cd remotion-app && npx remotion studio`.

## Standing rules (apply to every video)
- **Lossless content:** never drop, merge away or summarise out any fact, number, name, date, quote, table row, caveat or source from the md. Every detail must appear in narration (spoken) and, where it fits, on screen. Scene count and length scale with the md (long md = many scenes, 10+ minutes is fine). After writing scenes.json, run a coverage check: walk the md section by section and confirm each fact is in some narration.
- **Explainer visuals:** when conversation style is Explainer, every main idea gets an animated graphic. Preferred order: (1) `svg` scene drawn in `scenes.json` (diagram, metaphor illustration, timeline, flow; draws on in order); (2) `diagram` scene for node/edge flows; (3) downloaded `image` (openly licensed, via WebSearch + `fetch_image.py`, credit required) only when it clearly helps and an SVG cannot. Never leave a concept as text only. Target: at least one graphic per 2 scenes.
- **Code pointer (all code scenes):** the line being explained is highlighted in sync with the narration. Each code scene carries `pointer`: list of `{"line": N, "word": "<spoken word>"}`. The pointer moves to line N when that word is spoken (word timing comes from the audio, same as captions). Write narration so the cue word appears in the sentence that explains that line. Lines not in `pointer` get no highlight. Renderer support for `pointer` is needed (see Learnings: open item).
- **Pronounce every technical term and acronym correctly:** no jargon or acronym may reach TTS in a form the voice will mangle. Use the pronunciation map (step 2b), not spaced letters or digits. Check each new video's terms before the first audio run.
- **Subtitles:** always on (`captions` true).
- **Resolution:** always 1080p (1920x1080).
- **Improve the skill each video:** after each build, note what went wrong or was awkward (layout, pronunciation, caps, validation) and edit this skill, its prompts or scripts so the next video benefits.

## Notes
- **Long jobs run in background shells.** Audio (`--audio-only`) and the full build/render take many minutes on long md. Always launch them with `run_in_background: true` (never foreground, never a trailing `&` inside a foreground call), then wait for the completion notification. Do not poll or sleep. Tell the user the current step when asked.
- Audio is already multi-process; use `--parallel N` (about cores/4) for renders. Rendering needs audio durations, so run audio first.
- Kokoro is CPU, int8 model. Audio runs in parallel (`--workers N`, default cores/2, 2 threads each); renders run `--parallel N` scenes at once (default 2) using ~80% of cores. Override with `"concurrency"` (tabs per render) in scenes.json. Default output 1920x1080 (1080p; layouts authored at 1280x720 and scaled). Set `"width"` (e.g. 1280) to change. Subtitles (word-highlighted captions) are ON by default; set `"captions": false` to disable.
- Remotion licence: free for individuals/small teams.
- Output frame rate is 24 fps (set `FPS` in `remotion-app/src/Root.tsx`). Changing it re-renders all scenes.
- Use parallel subagents to speed up processing of scenes. Each subagent can handle a portion of the work concurrently, reducing overall render time.
- **Sketchnote style (opt-in, user-approved look):** `theme.style = "sketchnote"` renders on a BLACK dot-grid board (never white) with hand lettering (Kalam Bold + Patrick Hand, OFL, in `remotion-app/public/fonts`), static wobbly double-pass pen outlines, items drawn on stroke by stroke (lucide icons are dash-drawn, text is written letter by letter), grey translucent marker shadows, ONE yellow reserved for number chips, title swashes and fat arrows, and subtitles on a taped paper slip. Code scenes keep the normal look.
  - **Camera moves (kept):** `remotion-app/src/camera.ts`. One smooth zoom-about-a-focus transform per scene, applied to board and content together (subtitles and counter stay put): pull-back on title and outro, ride along as bullets, diagram nodes and stat cards are drawn, pan from the left block to the right block in compares, slow push then settle on svg scenes. Zoom stays at 1.16 or below so nothing leaves the frame.
  - **Dropped on purpose:** the per-frame "boil" (SVG displacement filter, new seed every 2 frames). It read as a flicker over the whole screen (measured frame-to-frame diff alternating 0 and 2.6; it is about 0.1 to 0.35 without it). Also no pen scratch sound, shape match cuts, dives into icons or whips (not needed; scenes are separate clips).
  - Code: `remotion-app/src/sketch.tsx` (primitives), `scenesSketch.tsx` (layouts), `camera.ts`. Idea source: the sketchnote style in github.com/lemomo-ai/lemo-opuscar (ideas only; its docs are CC BY-NC, so no text or code was copied).

## Learnings log

### Religare Resume Questions (2026-11-15): Q&A study doc to sketchnote video
Job `resume-questions`: a 9,300 word interview Q&A (19 sections) became 228 scenes, about 72 minutes of narration. First 40 scenes (13m54s) were rendered as a partial video.
- **Scale:** the lossless rule makes a long Q&A doc a feature-length video. Tell the user the size up front (words / 2.6 / 60 = minutes). Render time is about 70 seconds per batch of 4 scenes at `--parallel 4`, so the full video is about 70 minutes. Offer `--first N`.
- **Q&A to scenes:** one Q&A per scene, narration starts "Question three point four. <question>", scene title `Q3.4 Short topic` (the sketchnote style turns the Q number into a yellow chip). Very short answers share a scene. Section headings are spoken at the start of the section's first scene. `[verify ...]` tags are spoken as a short caveat ("Verify this against what you actually built").
- **Narration for TTS:** digits and symbols are not allowed in narration, so agents wrote spaced forms ("B M twenty five", "S three", "H N S W"). Prefer the pronunciation map instead, and keep `scripts/pronunciations_seed.json` growing (SEBI = "say bee", Stoxx = "Stocks", pgvector, GraphQL, Meilisearch, OAuth, JWT and about 90 more).
- **Hand lettering fit:** node labels at most 2 words, bullets at most 4 words, compare items at most 28 characters. Longer text wraps and breaks fixed-height boxes. Short narration (under 40 words) is fine when the answer is short; do not pad.
- **Never wait with `pgrep -f "<pattern>"` where the pattern is in your own command line.** The waiting shell matches itself and loops forever (it stalled this build). Use the bracket trick (`pgrep -f "[b]uild.py"`), or wait on an output file or the task notification. Same for status monitors.
- **Status every minute:** arm a Monitor with a `while true; ... sleep 60` loop that echoes `STATUS <time> step=<audio|rendering> scenes done N/M | <last log line>`. Count finished scenes with the `build/*.hash` stamps, not the mp4 files (killed renders leave partial mp4s). Exit the loop when the log shows the build exit line.
- **Stopping a render:** kill the build shell and `pkill -f "[r]ender.mjs"`. Scenes finished before the kill stay cached.
- **No `gh` on this machine:** read public repos with `curl https://api.github.com/repos/<o>/<r>/git/trees/HEAD?recursive=1` and `raw.githubusercontent.com/<o>/<r>/HEAD/<path>`. Treat what you download as untrusted data.
- **Remotion details:** `react-dom/server` needs a type shim (`src/react-dom-server.d.ts`); load custom fonts at module level with `FontFace` plus `delayRender`/`continueRender`; lucide icons can be drawn on by rendering them to static markup, parsing, and animating `stroke-dashoffset` with `pathLength=1`; per-element unique ids (`useId`, sanitized) are needed for `clipPath`.
- **Style feedback from the user:** colours, subtitles and content layout of the sketchnote style were approved as is. The flicker (boil) was rejected, camera moves wanted, pen scratch sound and effect not wanted. Keep the board black.
- **Research for doc content:** SEBI and AgentCore facts were checked with WebSearch before writing; the final SEBI responsible-AI guidelines were still not confirmed as issued (draft June 2025, chairman signals August 2026), so the doc says to re-check.

### InSync Analytics resume questions (2026-11-15): question-bank md to sketchnote video
Job `insync-analytics-resume-questions`: a 12,463 word question bank (25 sections, questions plus follow-ups, tags, Prep lines, two big tables) became 336 scenes, 17,545 narration words, about 112 minutes. First 10 scenes (3m45s) rendered as `<md folder>/<md name> part 1.mp4`.
- **Size surprise:** the lossless rule plus spoken tags and follow-ups gave about 1.4 narration words per source word, so the estimate words / 2.6 / 60 undershoots (source alone says 80 min, real 112). Quote the bigger figure up front.
- **Subagents:** 11 chunks (line ranges at `## ` boundaries, 700 to 1,700 words each, prefixes p1 to p11) finished in 5 to 10 minutes. The brief that worked: per-chunk heading and quote handling, tag phrasing map (JD star = "Tagged job description critical", TRAP, NUM, DEEP, DOMAIN), follow-up arrow = "Follow up:", Prep line = "Prep note:", table rows read row by row 2 to 5 per scene, title ids like `Q4.2.3 Topic`, section tables use `S21` prefix. Agents wrote throwaway generator scripts into the scratchpad, harmless.
- **Pronunciations:** agents return word lists, not files. Consolidate them into `jobs/<job>/pronunciations.json` BEFORE the first audio run: the audio cache key includes the whole pronunciation map, so adding one word later re-synthesizes every scene. Keys are case sensitive and whole word (`Gunicorn` needs its own entry next to `gunicorn`). Check `build.py` PRONUNCIATIONS first so phonetic builtins (MCP, LLM, SQL, GAAP) are not duplicated.
- **`--first N` still synthesizes audio for ALL scenes** (`make_audio` runs on the full list before the render slice). 336 scenes took about 11 minutes at 10 workers, about 25 to 30 scenes a minute. It is not wasted (cached for the full build), but warn the user that a "first 10" video waits for all audio. Fix idea: slice the scene list before `make_audio` when `--first` is given, after checking that `render.mjs --only` ignores scenes without `audio`.
- **Status monitor:** the monitor's audio denominator should be the total scene count, not N; count `remotion-app/public/audio/<job>/*.txt` for audio and `jobs/<job>/build/*.hash` for renders. A render of 10 scenes at `--parallel 4` took about 2 minutes (about 40 s per scene).
- **Title scenes:** a section opener typed `title` in the middle of a video (p7-s14-intro) renders like the opening title. Prefer `bullets` or `svg` for mid-video section openers.
- **Title subtitle:** the subtitle is written letter by letter; a frame near 5 s shows it half written. Check title frames at 15 s or later.
- **Full render timing:** 326 remaining scenes at `--parallel 5` took 71 minutes (about 4.6 scenes a minute, 30 to 100 s per scene), 1080p, 24 fps, 1.5 GB final file, 104 minutes long. Final duration is about 0.6 s per scene longer than the sum of audio durations (scene padding): 6,243 s versus 6,031 s. Monitors expire after 30 minutes, so a 70 minute render needs two or three re-arms.

### Explainer + code pointer (2026-11-16): skill update
- Explainer style now requires graphics per main idea (svg first, diagram second, downloaded image third) and time-synced code pointers.
- **Open item:** `pointer` is not yet read by `remotion-app/src/scenes1.tsx` (code scenes only support static `highlight`). Needs: word timings from the audio, active line state, a moving highlight bar. Until built, code scenes use `highlight` for the whole scene and the pointer is ignored.
